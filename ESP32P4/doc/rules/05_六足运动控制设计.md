## 1. 坐标系与命名约定

**本节的符号约定是唯一权威。** 代码中的符号必须与本节一致,否则关节方向会反向。

| 坐标系 | 定义 | 用途 |
|---|---|---|
| 机体坐标系 B | 原点在机体几何中心,x 向前,y 向左,z 向上 | 上层速度指令、姿态指令 |
| 单腿局部坐标系 L_i | 原点在腿根部安装点,x 沿径向外,y 沿切向,z 向上 | 逆运动学求解 |

**关节命名(每腿 3 DOF)**

| 关节 | 编号 | 轴 | 符号 | 正方向 |
|---|---|---|---|---|
| 髋偏转 coxa | q1 | 绕 z | θ_yaw | 逆时针(俯视)为正 |
| 大腿 femur | q2 | 绕 y(局部) | θ_femur | 抬腿方向为正 |
| 小腿 tibia | q3 | 绕 y(局部) | θ_tibia | 伸展为正(0 = 完全伸直) |

**腿部编号与安装角**(俯视,从机体上方看,y 轴向左,角度从 +x 逆时针为正)

| 腿号 | 安装角 φ_i | 位置 | 步态分组 |
|---|---|---|---|
| L1 | 30° | 左前 | A 组 |
| L2 | 90° | 左中(正左) | B 组 |
| L3 | 150° | 左后 | A 组 |
| L4 | 210° | 右后 | B 组 |
| L5 | 270° | 右中(正右) | A 组 |
| L6 | 330° | 右前 | B 组 |

三足步态下 A 组与 B 组交替支撑,构成两个稳定三角形。编号顺序绕机体逆时针一圈,便于机械装配与线束走线对应。

> **待确认**:六足均布角要按机械实际布局填。若采用"一足正前、一足正后"的布局(0°/60°/120°/180°/240°/300°),安装角、编号与步态分组都要改。机械冻结后本节必须更新。

## 2. 逆运动学

### 2.1 输入输出

```
输入:  P_B = (px, py, pz)  足端在机体坐标系的位置,单位 mm
       i                  腿号
输出:  q1, q2, q3         三个关节角,单位 rad
参数:  L0   腿根安装半径(机体中心到腿根)
       Lc   髋偏转连杆长度
       Lf   大腿长度
       Lt   小腿长度
```

### 2.2 求解步骤

**第 1 步:变换到腿局部坐标系**

腿根安装点 M_i = (L0·cosφ_i, L0·sinφ_i, 0)。把目标点绕 z 轴反向旋转 φ_i:

```
(dx, dy, dz) = Rz(-φ_i) · (P_B - M_i)
```

其中 `Rz(-φ)` 为:

```
dx =  cos(φ)·(px - Mx) + sin(φ)·(py - My)
dy = -sin(φ)·(px - Mx) + cos(φ)·(py - My)
dz =  pz
```

**第 2 步:髋偏转关节 q1**

```
q1 = atan2(dy, dx)
r  = sqrt(dx² + dy²) - Lc      /* 扣掉髋连杆后,到球面坐标的水平距离 */
```

**第 3 步:平面二连杆(大腿 + 小腿)**

在由 `r` 与竖直方向构成的平面内,令 ζ = -dz(向下为正):

```
D2 = r² + ζ²                              /* 髋到大腿根的距离平方 */
cos(θknee) = (Lf² + Lt² - D2) / (2·Lf·Lt)
cos(θknee) = clamp(cos(θknee), -0.99, 0.99)   /* 防止 acos 越界 */

θknee = acos(cos(θknee))                  /* 膝关节内角 ∈ [0, π] */
q3    = π - θknee                         /* 0 = 完全伸直 */

α     = acos( clamp( (Lf² + D2 - Lt²) / (2·Lf·sqrt(D2)), -1.0, 1.0 ) )
q2    = atan2(ζ, r) + α                   /* 膝盖朝后的构型 */
```

> 膝盖"朝前"还是"朝后"决定 q2 中 α 的符号。本项目建议采用**膝盖朝后**(与大多数六足机器人一致,离地间隙大);代码里把符号写成一个具名常量 `KNEE_SIGN`,不要散落在公式里。

### 2.3 必须处理的边界与异常

| 情况 | 处理 |
|---|---|
| D2 > (Lf+Lt)² | 目标超出可达范围:按比例缩到最大可达距离,返回 `E_RANGE`,并记录一次限幅事件 |
| D2 < |Lf-Lt|² | 目标太近:夹到最小距离,同上 |
| D2 ≈ 0 | 分母为 0:直接返回 `E_INVALID`,上层应保证不会发生 |
| q3 接近 0(完全伸直) | 力矩臂趋近 0,舵机负载剧增 → 关节限位必须禁止 q3 < 15° |
| q1 接近 ±90° | 髋关节线束与机械干涉 → 限位 ±60°(按机械实测) |

**关节限位必须硬编码在舵机层,而不是只写在文档里。** 上层任何指令都要经过限位,包括调试指令。

## 3. 步态引擎

### 3.1 输入与输出

```
输入:  vx, vy      机体坐标系期望速度 (mm/s)
       ωz         期望偏航角速度 (rad/s)
       h          期望机体高度 (mm)
       pose       期望姿态 (roll, pitch, yaw, x, y, z)
       gait       步态类型
       t          时间
输出:  6 个足端目标点(机体坐标系) → 送入 IK → 18 个关节角
```

### 3.2 步态定义

| 步态 | 支撑足数 | 占空比 β | 分组 | 特点 | 适用 |
|---|---|---|---|---|---|
| 三足步态 | 3 | 0.50 | {L1,L3,L5} 与 {L2,L4,L6} 交替 | 最快、最稳 | 平地正常行走 |
| 波动步态 | 5 | ≥0.83 | 依次单足摆动 | 最稳、最慢 | 窄小空间、演示 |
| 四足步态 | 4 | 0.67 | 两两交替 | 折中 | 一般过渡 |
| 自适应 | 动态 | 动态 | 按 IMU 与负载 | 抬腿高度与速度自适应 | 不平地面 |

### 3.3 摆动相与支撑相

对每只腿,相位 `φ_i ∈ [0,1)`;`φ_i < β` 为支撑相,否则为摆动相。

**支撑相**:足端在机体系里以速度反向移动(相当于机体相对地面前进):

```
v_foot_i = -( v_body + ωz × r_i )
```

其中 `r_i` 是从机体中心指向该足端当前落点的水平向量。逐周期积分得到落点位置,并保持 `pz = 落点高度`。

**摆动相**:从抬起点 A 到落点 B 做平滑插值,并叠加抬腿弧:

```
p(s) = A + (B - A) · smoothstep(s) + (0, 0, h_step · sin(π·s))
```

`s ∈ [0,1]` 是摆动相进度;`smoothstep(s) = 3s² - 2s³` 保证速度连续,避免舵机突变。

**下一落点的预测**:落点应补偿机体在这半个周期内的位移,否则会"拖步":

```
B_i = A_i_start_i + v_body · (T_swing) + 0.5·预测修正
```

实现上建议直接用"以机体中心为参考的半周期位移前馈",系数可调(参数 `stride_bias`)。

### 3.4 步态周期与步幅的关系

```
步幅 S = |v_horizontal| · β · T          /* T = 全周期时长 */
抬腿高度 h_step = clamp(0.25·S, 15mm, 60mm)
```

若 `S` 超过机械可达范围(由 L0/Lc/Lf/Lt 与关节限位决定),则自动降低速度并上报,不允许"尽力而为"地抬起。

### 3.5 稳定性:支撑多边形

三足步态下,支撑足构成一个三角形。机体重心(含舵机与电池)在地面的投影必须落在该三角形内部,且保留安全裕量。

```
margin = 重心投影到支撑三角形最近边的距离
要求: margin ≥ margin_min(建议 15-25mm,随速度提高而增大)
```

实现方式:每周期计算 `margin`;低于阈值时优先(1)降低速度,(2)降低机体高度,(3)平移机体使重心中置。

### 3.6 姿态指令的叠加顺序

```
P_foot_body = R(roll, pitch, yaw) · P_foot_nominal + T(x, y, z)
```

**顺序必须固定**:先做旋转再平移。旋转矩阵用 ZYX 顺序(先 yaw 再 pitch 再 roll),与上层姿态指令的语义一致。顺序改了会导致"低头"变成"侧倾"。

### 3.7 状态机(运动视角)

| 状态 | 进入条件 | 行为 | 退出 |
|---|---|---|---|
| BOOT | 上电 | 自检,舵机不上电 | 自检通过 |
| INIT | 自检通过 | **读总线舵机位置确认髋/大腿正常**;缓慢抬到标准站姿;小腿靠电流监测防卡死 | 总线位置合理 + 电流正常 + 姿态稳定 |
| IDLE | 站立稳定 | 保持站姿,微幅呼吸动作 | 收到速度指令 |
| WALK | v 或 ω 非零 | 按步态行走 | 速度归零 |
| ACTION | 收到动作指令 | 播放预定义动作序列 | 序列结束 |
| SIT | 收到 CMD_SIT | 缓慢降低机体,收腿 | 收到 CMD_STAND |
| SAFE_HOLD | 主链路失联 | 停止运动,保持当前姿态,腿不下电 | 链路恢复 |
| FAULT | 自检失败或标定无效 | 舵机断电,状态灯告警 | 复位 |
| ESTOP | 急停 | PWM 关断 + 舵机断电 | 显式清除且安全检查通过 |

**INIT 的电流保护**:如果抬腿时舵机电流超过阈值且位置不变化,说明卡住,必须立即停止并进入 FAULT,不允许持续加力(会烧舵机)。

## 4. 舵机标定

### 4.0 舵机参数(2026-09-27 第二次改版:髋/大腿走总线,小腿走 PWM)

**本节参数适用于小腿 MG996R。** 髋与大腿已改用总线舵机,它们有位置、负载与温度反馈,标定方式不同(见 §4.4),并且它们的角度**不再需要靠标定表推断**。

| 参数 | 值 |
|---|---|
| 类型 | 模拟舵机,**无位置反馈** |
| 供电 | 6.0-6.5V(M3 降压后) |
| PWM | 50Hz,脉宽 500-2500µs 对应约 180° 行程 |
| 灵敏度 | 约 **0.09°/µs**(2000µs 对应 180°),即 1° 约需 11µs |
| 死区 | 约 5µs ≈ 0.45° |
| 堵转扭矩 | 11 kg·cm ≈ 1.08 N·m @6V |
| 重量 | 约 55g |

由此得到两条设计结论:

1. **控制分辨率上限约 0.45°**,再细的指令没有意义(机械间隙通常更大)。IK 输出的角度要先量化到约 0.5° 再转脉宽,避免舵机持续在死区边缘抖动。
2. **无位置反馈意味着"标定表"就是唯一的真值来源**。上电后无法回读舵机实际位置,所以每次上电必须先缓动到机械中位再进入工作状态(见文档 05 §3.7 的 INIT 状态)。

### 4.1 标定流程

| 步骤 | 做法 | 记录 |
|---|---|---|
| 1. 机械中位 | 手动把每个关节摆到机械中位(几何定义的中位角) | 拍照存档 |
| 2. 脉宽中位 | 逐个输出脉宽直到关节处于机械中位 | 记录中位脉宽 center_us |
| 3. 方向 | 输出 +100us,观察关节转动方向 | 记录 dir = +1 或 -1 |
| 4. 限位 | 缓慢逼近机械限位,记录最小与最大安全脉宽 | min_us / max_us |
| 5. 写入 | 存入内部 Flash 与外部 Flash 双份加 CRC | 版本号与日期 |
| 6. 验证 | 断电重启后读回,再跑一次到位精度测试 | 误差应小于 5 度 |

### 4.2 标定表结构

```c
typedef struct {
    int16_t center_us;   /* 关节角 0 对应的脉宽 */
    int16_t min_us;      /* 安全下限 */
    int16_t max_us;      /* 安全上限 */
    int16_t cdeg_per_us; /* 灵敏度(标定时实测) */
    int8_t  dir;         /* 方向 */
    int8_t  reserved;
} joint_cal_t;

typedef struct {
    uint32_t   version;
    uint16_t   crc;
    joint_cal_t joints[18];
} cal_table_t;
```

### 4.3 角度到脉宽的换算

```
pulse_us = center_us + dir · (angle_cdeg / sens_cdeg_per_us)
pulse_us = clamp(pulse_us, min_us, max_us)

MG996R 参考值:sens_cdeg_per_us 约 9(即 0.09 度/us)
例:angle = 9000 cdeg(90 度),center = 1500 -> pulse = 1500 + 9000/9 = 2500us
```

**限幅在换算函数内完成,而不是由调用者保证。** 这样任何路径(包括调试指令)都无法越限。

**必须先量化再换算**:把 `angle_cdeg` 四舍五入到 50 cdeg(0.5 度)后再算脉宽,否则会出现"指令变了但舵机不动"的假象(落在死区内),排障时极易误判成通信问题。

### 4.4 总线舵机的标定(髋与大腿,12 个关节)

总线舵机自带位置反馈,标定的性质与 MG996R 完全不同:**不需要"角度到脉宽"的映射,而需要"舵机内部计数到机械关节角"的映射与零点对齐。**

| 步骤 | 做法 | 记录 |
|---|---|---|
| 1. 分配节点 ID | 给 12 个舵机分配唯一总线 ID,并记录"物理位置 ↔ ID"对应表 | 节点表(必须存 Flash) |
| 2. 零点对齐 | 手动摆到机械零点,读出并记录该位置的原始计数(offset) | offset[12] |
| 3. 方向 | 命令 +10 度,观察关节转动方向 | dir[12] = ±1 |
| 4. 限位 | 逐个逼近机械限位,记录安全角度上限 | min_deg / max_deg |
| 5. 力矩上限 | 设定每个关节的最大输出力矩(建议为标称的 60-70%) | torque_limit[12] |
| 6. 写入与验证 | 存 Flash 双份加 CRC;断电重启后读回并复测到位精度 | 误差应小于 1 度 |

**节点表是最容易出错的一项**:12 个舵机装在不同的机械位置,一旦 ID 与位置对错,机器人会做出"完全错误但看起来在动"的动作。建议在装配工艺里规定"先单独上电读 ID,再装到腿上"。

**利用总线舵机的新能力**

| 能力 | 在控制里的用法 |
|---|---|
| 位置反馈 | 髋/大腿角度直接进 IK 反馈,足端定位误差只剩小腿贡献 |
| 负载反馈 | 直接判断关节是否过载,比电流推断可靠;可用于落地检测与地形适应 |
| 温度反馈 | 提前发现异常发热(卡死或摩擦过大) |
| 力矩上限 | 设为标称的 60-70%,从源头避免自伤与夹伤 |
| 可命令卸力模式 | 急停或掉电前可做"阻尼下降",避免 MG996R 那种自由落体 |

## 5. 动作库(ACTION)

动作是"关节空间或足端空间的预定义轨迹",由上层用 `CMD_ACTION` 触发。动作执行期间由步态引擎接管,禁止并发运动指令(默认返回 E_BUSY)。

| action_id | 名称 | 描述 | 时长(估算) |
|---|---|---|---|
| 0x01 | 点头 | 机体前后小幅俯仰 3 次 | 2s |
| 0x02 | 摇头 | 偏航左右摆动 3 次 | 2s |
| 0x03 | 抬手打招呼 | 前右腿抬起并摆动 | 2.5s |
| 0x04 | 坐下 | 降低机体并收腿 | 3s |
| 0x05 | 站立 | 从坐姿恢复站姿 | 3s |
| 0x06 | 小舞步 | 原地左右踏步 + 机体摆动 | 5s |
| 0x07 | 伸懒腰 | 先低后高,前后拉伸 | 3s |
| 0x08 | 吓一跳 | 快速后撤 + 机体上抬 | 1.5s |
| 0x09 | 兴奋 | 快速上下跳动 4 次 | 3s |
| 0x10 | 放松 | 缓慢趴下但保持抬头的休息姿态 | 4s |

动作实现方式:

1. **关键帧 + 插值**:每个动作定义为若干关键帧(机体位姿与足端位置),用 smoothstep 插值
2. **必须做稳定性检查**:每帧计算支撑多边形裕量,动作设计阶段就应保证裕量不被破坏
3. **动作可被打断**:急停与安全事件在任何时刻可打断;可选配置为收到新速度指令时打断

## 6. 代码形状(示意骨架)

核心逻辑保持纯函数与显式上下文,**不包含任何 HAL 头文件**,以便在 PC 上单元测试。

```c
/* robot_math.h —— 纯逻辑,可 PC 测试 */
typedef struct { float x, y, z; } vec3_t;

/* ik_solver.h */
typedef struct {
    float L0, Lc, Lf, Lt;      /* 机械常数 */
    float q1_min, q1_max;      /* 关节限位,rad */
    float q2_min, q2_max;
    float q3_min, q3_max;
    float knee_sign;           /* +1 或 -1,决定膝盖构型 */
} ik_config_t;

typedef struct { float q1, q2, q3; } joint_angles_t;

typedef enum {
    IK_OK = 0,
    IK_ERR_RANGE,      /* 目标不可达,已被限幅 */
    IK_ERR_INVALID,    /* 输入非法 */
    IK_ERR_LIMIT       /* 解出的关节角超限 */
} ik_result_t;

ik_result_t ik_solve(const ik_config_t *cfg, uint8_t leg, vec3_t foot_B, joint_angles_t *out);

/* gait_engine.h */
typedef struct {
    uint8_t  gait;             /* 步态类型 */
    float    duty;             /* 占空比 β */
    float    period_s;         /* 全周期 T */
    float    step_h_mm;
    float    margin_min_mm;    /* 稳定性裕量下限 */
    float    stride_bias;
} gait_config_t;

typedef struct {
    float    phase;            /* 0..1 */
    vec3_t   stance_foot[6];   /* 支撑足当前落点 */
    uint32_t last_update_ms;
} gait_state_t;

typedef struct {
    float vx, vy, wz;          /* 上层意图 */
    vec3_t body_t;             /* 机体平移 */
    float roll, pitch, yaw;    /* 机体姿态 */
    float height_mm;
} motion_intent_t;

typedef struct {
    joint_angles_t joints[6];
    float stability_margin_mm;
    uint8_t flags;             /* 限幅/不可达/裕量不足等 */
} gait_output_t;

gait_result_t gait_step(const gait_config_t *cfg, gait_state_t *st, uint32_t now_ms,
                        const motion_intent_t *intent, gait_output_t *out);
```

**设计要点**

| 要点 | 说明 |
|---|---|
| 配置与状态分离 | `ik_config_t` / `gait_config_t` 是常量;状态在 `gait_state_t` / `joint_angles_t` |
| 多实例 | 允许创建多个 `gait_state_t` 做仿真对比(例如不同步态的离线对比) |
| 无隐藏全局 | 所有状态通过参数传入,便于测试 |
| 返回结构化错误 | 用 `ik_result_t` 而非 -1 |
| 单位统一 | 长度 mm,角度 rad(对外协议为 0.01 度,在协议层换算) |

## 7. 验证策略

| 层级 | 验证内容 | 方法 | 通过判据 |
|---|---|---|---|
| IK 单元测试 | 正解与逆解往返一致 | PC 上随机 10000 个可达点做 round-trip | 位置误差 < 0.01mm |
| IK 边界 | 不可达、极限伸展、奇异点 | 定点测试集 | 返回正确错误码且不产生 NaN |
| 步态仿真 | 足端轨迹连续性 | PC 上跑 1000 周期,检查速度与加速度 | 无突变(加速度有界) |
| 稳定性 | 支撑多边形裕量 | 仿真遍历速度与姿态组合 | 始终满足 margin 下限 |
| 静态精度 | 单关节到位误差 | 量角器或 IMU 辅助 | 误差 < 5 度 |
| 动态稳定 | 原地走、直线走、原地转 | 实机 + 视频记录 | 不摔、不拖步、不外八 |
| 负载 | 加配重后行走 | 逐步加配重 | 达到设计负载且电流在阈值内 |
| 续航 | 连续行走 | 功率计 + 计时 | 达到目标续航 |
