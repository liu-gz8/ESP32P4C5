## 1. 结论摘要(先看这个)

1. **实物是一块 OSPTEK(鱼鹰光电)`ESP32-P4-Module` 基础底板,不是文档里设想的自制三模块板。**
   它把 P4、C5、摄像头、480×480 MIPI 屏、触摸、音频、TF 卡、USB 都做在一块板上。
2. **P4 与 C5 之间走 SDIO + ESP-Hosted,不是文档 02/07 假设的 SPI。** C5 作为从机,
   P4 用 `esp_wifi_remote` 把 Wi-Fi/BLE 当本地外设使用。这直接影响链路层设计:
   不需要自己写 P4↔C5 的 SPI 协议,但要按 ESP-Hosted 的约束来。
3. **文档 01~09 里的"打样前阻塞项"大部分**在这块模组上已经**自动关闭**,因为摄像头、
   屏、触摸、音频、无线都已经由模组厂商做过验证并跑通过(见 §2 的启动日志)。
4. **README 里承诺的 `include/robot_link.h` 与 `tools/robot_link_ref.py` 在工作区里并不存在**
   (文档 00 的交付清单与文档 03 的"参考实现"引用了它们)。协议层需要补齐后才能真正开工联调。
5. ESP-IDF 的 Python 环境原本是**坏的**(见 §4),已在本工作区修好并验证可以完整编译。

## 4. 开发环境:原始状态与修复

### 4.1 原始状态(为什么一开始编不了)

| 项 | 状态 |
|---|---|
| ESP-IDF | `D:\ESP-IDF\.espressif\v6.1\esp-idf`,v6.1.0(工程 sdkconfig 的 target 为 esp32p4) |
| 工具链 | `C:\Espressif\tools\riscv32-esp-elf\esp-15.2.0_20251204`(P4 是 RISC-V,不是 Xtensa) |
| **Python** | **坏的**:`C:\Espressif\tools\python\v6.1\venv` 指向 `…\Programs\Python\Python311\python.exe`,而该 Python 已从本机卸载 → `idf.py` 完全无法启动 |
| 组件缓存 | 完好(见 §3) |

### 4.2 修复方式(已在本工作区落地)

- 用 PlatformIO 自带的 Python 3.11.7(`C:\Users\Administrator\.platformio\penv`)新建了一个 venv:
  `D:\ESP32P4C5\.tools\idf_py_venv`,并把旧 venv 里**仍然完好的 IDF Python 依赖**
(esptool 5.4.0、esp-idf-monitor、esp-idf-kconfig、click、cryptography、pydantic…)整体复制进去。
全部是 cp311 的包,与新 venv 的 3.11.7 兼容。**没有联网,没有改动机器上任何原有目录。**
- `D:\ESP32P4C5\tools\idf.ps1` 把环境变量、工具链 PATH、ccache、ROM ELF 目录、git safe.directory 全部设好,
  并导出 `idf` 命令。

### 4.3 用法

```powershell
. D:\ESP32P4C5\tools\idf.ps1
cd D:\ESP32P4C5\ESP32P4\ESP32-P4
idf build
idf -p COM6 flash monitor
```

**已验证**:`idf build` 从干净目录完整编译通过,产出 `build/ESP32-P4.bin`(约 192KB)。

### 4.4 两个必须注意的环境坑

1. **本沙箱不给 python 子进程继承 shell 的 PATH**。直接用 `.ps1` 里设 `$env:PATH` 后跑 `idf.py`,
   CMake 会找不到 ninja/ccache。所以 `idf.ps1` 里的 `idf` 函数是用 `ProcessStartInfo`
   显式构造环境变量的,**不要绕过它去直接调 `idf.py`**。
2. **ccache 默认缓存在 `%LOCALAPPDATA%\ccache`**,沙箱无写权限会报
   `ccache: error: Permission denied`。修复脚本已把 `CCACHE_DIR` 指到工作区内。

**关键结论**:
- **相机通路已解决**:`esp_video 2.5.0 + esp_ipa 2.4.0 + esp_cam_sensor 2.6.0` 在 IDF 6.1 上编译通过,
  不需要改任何源码,只需把依赖版本从厂商锁定的 `0.8.*` 放开。
- **显示通路需要自己写**:厂商 `hw_init` 组件用的是 IDF 6.0 的 DPI API
  (`pixel_format` / `LCD_COLOR_PIXEL_FORMAT_RGB565` / `.flags.use_dma2d` 都已在 6.1 移除或改名)。
  但 `esp_lcd_st7102` 面板驱动本身只需一处改动即可复用。
